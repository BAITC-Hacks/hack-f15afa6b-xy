## Ситуационный центр · 24.09.2026

Ветка `feat/operator-demo`, основа — этот репозиторий. GovTech / Pulse 109 не связан с HackAlem.
На `/` доступны очередь, playbooks с preview и подтверждением, Radar, управление инцидентами,
взвешенная маршрутизация, присутствие операторов и команды Ctrl/Cmd+K. Исходный интерфейс — `/legacy`.
Все демонстрационные данные синтетические; обученных моделей и внешней доставки нет.

[Отчёт о реализации, тестах и сценарий демонстрации](docs/operations-delivery.md).
Для нового всплеска: **Радар → Демо-всплеск → Посмотреть обращения → Создать инцидент**.
Существующая SQLite-база сохраняет решения. Для чистого демо задайте новый `DATABASE_PATH`, не удаляйте рабочую базу.

### Laya triage

Laya подключается как изолированный decision layer перед существующей маршрутизацией. Режимы
`mock`, `existing_classifier`, `laya` и `hybrid` выбираются через `P109_DECISION_PROVIDER`;
локальный и удалённый сервер используют один HTTP-контракт. Ошибка Laya не останавливает Pulse,
а сомнительные решения остаются за оператором. Конфигурация, запуск, fallback, проверки и честные
ограничения описаны в [docs/laya-integration.md](docs/laya-integration.md); пример ENV — `.env.example`.

Проверки новых серверных функций запускают свои временные БД:
```sh
python scripts/check_playbooks.py
python scripts/check_incidents.py
python scripts/check_routing.py
```
Браузерные сценарии `check_demo_ui.cjs`, `check_playbooks_ui.cjs`, `check_incidents_ui.cjs`,
`check_support_ui.cjs` запускаются через Node с внешним Playwright; первый аргумент — адрес тестового сервера.
Для demo и playbooks нужны отдельные свежие синтетические БД. CI содержит команды запуска.

## Что готово

На 10.09.2026: реализован первый синтетический вертикальный срез (issue P109-09): FastAPI-приложение (`app.py`), веб-интерфейс оператора (`static/`), детерминированные синтетические фикстуры (`fixtures/demo.json`) на 10 тем (RU/KK) и 20 регионов, SQLite-хранилище, аудит событий и автоматический smoke-тест (`scripts/smoke.py`). **Обученных моделей ещё нет** (режим `mock`, статус `not_trained`, checkpoint_id=null; модули уведомлений, прогноза, запросов и экспорта возвращают честный 501).

Добавлен независимый компонент покрытия (часть P109-26): 20 регионов в матрице, 7 с файлами / 13 без файлов, фильтры, проверенные локальные количества CSV-записей и явные непроверенные поля/история. Источники — существующие inventory/matrix; API не читает CSV или обращения. Синтетические счётчики отделены от сведений о пакете.

Локальный структурный аудит восьми файлов: **1 036 858 CSV-записей**, без ошибок структуры; размеры и заголовки совпали с inventory. Это не число уникальных обращений и не проверка полной идентичности Drive. Полнота истории, смысл исходного текста/решений и RU/KK не подтверждены; тринадцать регионов отсутствуют в полученном пакете. P109-26 остаётся частично выполненной: динамика, проверенные агрегаты и другие критерии требуют P109-25.

## Запуск и проверка

1. Изолированное окружение (Python 3.11+):
```sh
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
```
В PowerShell: `py -3 -m venv .venv`, затем `& .venv/Scripts/Activate.ps1` и `$env:PYTHONUTF8='1'`. Если activation ограничен, вызывайте `.venv/Scripts/python.exe` напрямую. Зафиксированные версии фактической проверки: Python 3.12.14, FastAPI 0.141.1, Uvicorn 0.52.4, Pydantic 2.13.5, NumPy 2.5.3; файл requirements сохраняет исходные диапазоны, lockfile пока нет.

2. Запуск автоматического smoke-теста (изолированная временная БД и локальный сервер):
```sh
python3 scripts/smoke.py
```

3. Запуск веб-приложения:
```sh
python3 -m uvicorn app:app --host 127.0.0.1 --port 8000 --reload
```
Интерфейс доступен по адресу: `http://127.0.0.1:8000` (баннер `SYNTHETIC DEMO — MODELS NOT TRAINED`).

4. Проверка артефактов планирования:
```sh
python3 scripts/check_plan.py
python3 scripts/check_coverage.py
python3 scripts/test_audit_received_csv.py
```

`/api/data-coverage?region_id=KZ-ALM` возвращает выбранный регион; summary всегда относится ко всему пакету. Неизвестный/пустой ID → 422; отсутствующие или рассогласованные файлы планирования → безопасный 503. Частичный локальный подсчёт не превращается в сумму по региону. `record_count` — CSV-записи, неизвестное — `null`. Ни один статус заголовка не подтверждает семантику содержимого. SQLite-схема и контракт решений не менялись.

Локальный аудит (папка CSV вне репозитория; отчёт по умолчанию в игнорируемом `data/`):
```sh
python3 scripts/audit_received_csv.py --source-dir "/path/to/received-csv"
```
Скрипт выводит только числовые профили и фиксированные статусы; не передаёт данные в сеть, не выводит значения/примеры и не изменяет CSV. Результаты не являются гарантией обезличивания; не коммитьте исходные файлы или промежуточные данные. Для обучения отдельно нужны разрешения, семантика, версии корпуса и разбиение без утечки.

Необязательная браузерная регрессия (Node + Playwright 1.62.1, вне runtime приложения):
```sh
npm install --prefix ../pulse109-browser-check --no-save playwright@1.62.1
NODE_PATH=../pulse109-browser-check/node_modules node scripts/check_coverage_ui.cjs http://127.0.0.1:8000
```
В PowerShell сначала `$env:NODE_PATH='../pulse109-browser-check/node_modules'`, затем `node scripts/check_coverage_ui.cjs http://127.0.0.1:8000`. По умолчанию используется установленный Edge. Для Chromium: установить browser через Playwright CLI и задать `P109_BROWSER=chromium`. Проверяются загрузка, клавиатура, пустое состояние, регион/наличие файла, 503/повтор, устаревший ответ, мобильная ширина; сервер предварительно запускается командой выше. Третий аргумент — необязательный путь безопасного screenshot. Использовать только отдельную синтетическую БД, не реальный импорт.
